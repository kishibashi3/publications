# 自己改訂規範アーキテクチャ v1

2026-09-19 · Kazuhiro

本書は、自らを改訂する規範の体系の最小の骨格を定める。本書は内側の規範を参照しない。最初の改訂の循環を回すのに要るものだけを置き、それ以外は、必要になった時点で記録を根拠に追加する。

## 1. 規範文書が持つもの

| 項目 | 内容 |
| --- | --- |
| 目的 | 何を目指すか |
| ルール | 何に従って行動するか |
| 実行者 | 誰が規範文書に従って行動するか |
| 所有者 | 誰が変更を承認するか。人間とする |
| 観測 | 見直しの根拠として何を記録するか |
| 見直しの契機 | いつ見直すか |
| 準拠先 | 従う上位の規範文書と、その版 |

## 2. 改訂

- 評価・改訂の提起・採否を、追記のみの記録に残す
- 所有者が承認した改訂を、新しい版とする
- 実行者は、自らを縛る規範文書の改訂を承認しない

## 3. 版

- 規範文書は git で管理する。ファイル名に版を持たせない。版は本文の冒頭に書く
- 版は改訂ごとに一つ増える識別子とし、大小の順序以外の意味を持たない
- 版の実体は、所有者が承認した改訂の commit とする。承認と同時に `<文書名>/v<版>` の tag を打ち、以後その commit を変更しない
- 草案は版を持たない。承認された時点で版が付く
- 追記のみの記録には、版ごとに、日付・所有者・変更の要旨・根拠とした観測を一行残す

## 4. 参照

- 規範文書は、準拠先を版を明示して参照する。参照は tag で解決する
- 上位の版が上がっても、下位は自動では追随しない。移行するかは下位の所有者が決め、記録に残す。移行しない間も、下位が指す版は tag として残る
- 参照は下位から上位への一方向とし、上位の規範文書は下位を参照しない

## 5. 本書の変更

本書は第2章の手続きでは改訂しない。変更は新しい版で置き換え、採用者が移行するかを選ぶ。本書の観測は、内側の改訂では解けなかった構造上の問題の記録とする。

## 6. 後回しにしたもの

型の定義、層の全順序、項目ごとの反証・見直し条件、独立した判定者、価値の必須化は、現時点では置かない。困った事例が記録された時点で、それを根拠に追加する。
