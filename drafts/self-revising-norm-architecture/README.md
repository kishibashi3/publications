# 自己改訂規範アーキテクチャ

規範の所有者、改訂の承認、観測と記録、準拠先と版の参照を定める共通基盤。
AA固有の開発原則やEAA固有のCell間手順とは分けて管理する。

## 文書

| 文書 | 内容 |
| --- | --- |
| [最小構成](self-revising-norm-architecture-minimal.md) | 改訂の循環を成立させる最小の項目・改訂・参照 |
| [詳細記述](self-revising-norm-architecture.md) | 規範項目、Git・tagによる版管理などを含む記述 |

AAの準拠先と本草案群の説明でいうv1は、所有者による承認を明記した最小構成を指す。
詳細記述もv1を掲げているが、承認条件などの記述が異なる別文書であり、同じ版の代替として扱わない。
今回の整理は参照文書を特定するもので、最小構成の承認済み本文は変更しない。

## なぜ独立したアーキテクチャが必要か

Agentが規範を改善するには、文書を書けることと、その変更に効力を与えられることを分ける必要がある。
所有者・改訂記録・承認・採用版を、個別の開発原則から独立して定める。これにより、開発原則を変えるたびに改訂手続きまで作り直す必要がなくなる。

この手続き自体の正当性を同じ手続きだけで成立させることはできない。信頼の根は外部の人間の承認で与え、内側の規範の改訂をその根に従わせる。これが最小構成 §4 の位置づけである。

§3 の参照方向は規範の準拠関係を扱う。観測記録や業務知識を読む方向、改善提案を送る方向を制限するものではない。
文書の所有、改訂の提起、承認、採用は別の行為である。Agentによる編集だけでは承認や採用は成立しない。

最小構成 §2 は提起者と承認者を分ける。人間の所有者が自ら提起した場合も、自動的な例外にはならない。別の正当な承認者を置けない場合の扱いは、根の外で決める必要がある未決事項である。
