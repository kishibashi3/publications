AGENTIC AGILE ／ 紹介 1 of 4

二つの崩れ方のあいだ

Agent に開発を任せるとき、誰もが試す二つのやり方があります。どちらも壊れます。AA と EAA は、その間を通るために要るものだけを書いたものです。

崩れ方 A

人間が、全部を承認する

出力を一つずつ人間が確認する。安全に見えます。けれど実行が安く速くなるほど、確認待ちの列が伸びる。速くなったのは実行のほうで、判断は速くなっていない。Agent を増やすほど、先に尽きるのは人間の時間になります。

崩れ方 B

Agent に、判断も任せる

待ちをなくすには任せるしかない。けれど任せた先で、実行者が自分を縛る規則を自分で緩められるなら、規則は規則ではなくなる。検証の無効化も権限の拡大も「必要だと判断した」で通り、ほかのすべての取り決めが、外してよいものに変わります。

この二つのあいだに、
通れる道はあるか。

01 ／ 前提

前提は、三つで足りる。

置いているのは、Agent が主要な実行主体になった環境です。以下の「実行」と「出力」は、その Agent のものを指します。

  • 実行は安く、速いが、総量には上限がある。
  • 希少なのは、人間の判断と、実行の総量である。
  • 出力は確率的にばらつき、同じ生成元は同じ誤りを共有する。

安くなったのは Agent の実行です。人間の判断は、希少なままです。一行目と二行目が噛み合うのは、この二つが別物だからです。実装能力の希少性が下がったこと、これがこの原則群の出発点です。

二行目の「希少」は、二つの違うものを指しています。人間の判断は、一件あたりが高く、絶対量も少ない。実行の総量のほうは、人間と比べれば桁違いに大きい。それでも希少と呼ぶのは、比べている相手が人間ではなく需要だからです。

正確には、値段がゼロなら使いたい量と比べています。単価が下がるほど、試したいことは際限なく増えます。仮説を十本立てて全部走らせる、総当たりで確かめる、駄目なら捨ててやり直す。単価が高かった頃には候補にすら挙がらなかった使い方が、安くなった瞬間に全部現実味を持つ。だから総量がどれだけ大きくても、枠にはぶつかります。

この前提が効いてくるのは一点、使えば減るというところです。誤った方向へ流した量は、後で使える量から引かれる。上限がなければ、誤り確率がいくら高くても量を流すことに値段がつかず、(6)（範囲は可逆性で、速度は期待浪費で決める）の期待浪費は、尺度になりません。必要なのはそこまでです。

書かれていない前提もあります。人が有限であること、要求が変わること。前提としては正しいけれど、以前と変わっていない。変わっていない前提から出る結論は、以前と同じ結論になります。だから書かない。

この三つは、互いに噛み合っています。実行が安いから何度でも試せる。何度でも試せるから人間が全部は見られない。見られないから、判断をどこに置くかが問題になる。ただし総量に上限があるので、試すこと自体にも値段がつく。そして出力がばらつくので、一度見て良かったことは、次も良いことを保証しない。

点で確かめる方法が効かなくなるのは、
この三つが同時に成り立つときです。

02 ／ 細い道

一つ抜くと、
どちらかの側に落ちる。

以下の八つは、順番に依存しています。前のものを土台にして次が立ち、どれを抜いたときにどちらへ落ちるかが決まっています。

  1. 書かれたものだけが効く

    判断をどこに置くかを設計するには、まず置き場所が特定できなければならない。だから、従うのは書かれたルールと書かれた価値だけとする。

    ここで止めず、書かれていないものは、存在しないものとして扱うまで踏み込んでいます。人間の実行者は書かれていない前提を持っていて、それが機能したのは、同じ環境に長くいて、外れたときに周囲が止めたからです。Agent にはそれがない。文脈は毎回組み立て直される。そして書かれていないものを参照しようとしたとき、Agent は「参照できませんでした」とは言わず、もっともらしく埋める。埋め方は確率的なので、同じ欠落が毎回同じようには埋まりません。

    「書かれていないが弱い権威はある」を許すと、この確率的な穴埋めに権威を与えることになります。代償はあります。書かれていない良い慣行は、いったん効力を失う。ただし失われたままにはならず、妨げになった事例として現れ、書かれた時点で戻ってくる。良い慣行を否定しているのではなく、通る経路を一本にしています。

    抜くと「誰かが暗黙に見ている」が成立し、判断の配分は測ることも変えることもできなくなる。崩れ方 A へ。

  2. 規範は、改訂される

    前提は動きます。規範が固定なら、前提が変わったとき実行者にできるのは「従って失敗する」か「黙って外す」かのどちらかです。どちらも記録に残らない。改訂を手続きにすると、前提が変わったという事実そのものが記録として残ります。

    そして、改訂できるのは対象があるものだけです。暗黙の運用が権威を持ちうるなら、規範を改訂しても実行は変わらないことがあり、変わらなかった理由も残せない。(1) がなければ (2) は空文になります。

    抜くと黙って外すほうが選ばれ、しかも記録に残らない。崩れ方 B へ、気づかないまま。

  3. 執行と立法を、同じ層に置く

    従来の階層は役割で分かれていました。上が方針を決め、下が実行する。ここではそうしません。各層が、自らの規範に従って執行し、かつ下位の規範を書きます。

    執行だけの層は、現実に触れて不具合を見つけても、反映する先を持ちません。下位を書くだけの層は、自分では執行していないので観測がない。同じ主体が両方をやるとき、執行で得た観測が、そのまま下位の改訂根拠になります。この経路を作るために、二重性が要ります。

  4. ただし、提起した者は承認しない

    (3) をそのまま置けば、自分に都合のよい規範を自分で書けてしまう。そこで非対称を一つだけ入れます。執行しながら下位を書くことは許し、自分が提起した改訂を自分で承認することは許さない。承認するのは、その規範文書の所有者です。

    この一つの非対称が、二重性を利益相反にしないための荷重を、ほぼ全部持っています。

    抜くと執行も立法も承認も同じ主体に閉じる。崩れ方 B そのもの。

  5. 層は、誰がいるかで定義しない

    層は「何に従い、何を書くか」という関係で決まります。人間が担当している層と Agent が担当している層は、構造としては同じものです。

    だから委任が進んで実行主体が入れ替わっても、規範を書き直す必要がない。既存の枠組みとの分かれ目がここです。工程に Agent を差し込む形でもなく、人の役割を Agent に割り当てる形でもない。どちらも、層を役割で定義したままの拡張です。

  6. 範囲は可逆性で、速度は期待浪費で決める

    範囲について。取り消せない操作をどこで止めるかは、能力の評価ではなく、層の境界をどこに置くかという問題です。

    速度について。期待浪費 ＝ 誤り確率 × 誤ったまま進む実行量。誤り確率 10% で 1 単位進むなら 0.1、1% で 10,000 単位進むなら 100。実行の総量に上限があるからこそ、誤った方向に流した量が損失になります。上限がなければ、量を流すことに値段がつかず、この尺度は成立しません。

    可逆性は操作の種別から、実行量は記録から決まります。どちらも実行者の自己申告を経ません。

  7. 可逆性は、設計で買える

    小さく刻めば、取り消せる範囲が広がります。標準的なアジャイルも「小さく刻め」と求めますが、そちらでは処方であり、守らせるには規律が要る。(6) の下では、刻まなければ自分が止まる。処方が帰結に変わります。

    但し書き各段階が可逆でも累積が不可逆なら、買えたのは見かけの可逆性でしかない。判断する対象は、そのときは累積のほうです。

  8. 自分の権限だけは、刻んでも買えない

    権限を緩める操作は、設定としては取り消せることが多い。けれど実行は安く速いので、緩めてから戻すまでの窓のあいだに、承認を通さない実行が何回でも入ります。取り消せるのは設定だけで、窓のあいだに出た効果はそのまま残ります。

    可逆性と権限増加は、独立に決まる軸です。可逆かつ権限増加という組み合わせは実在します。(6) は範囲を可逆性で決めると言っているので、これを別に立てないと、その組み合わせは自律の側に落ちます。

    抜くと「可逆だから安全」という、正しそうな理屈を通って 崩れ方 B へ落ちる。

そして一つ、床があります。「不要な判断をなくすことも成果である」——これは人間の判断を減らす側の指針で、削れる範囲は広い。その下限が (8) です。ここを削った時点で、ほかのすべての取り決めが「実行者が必要と判断すれば外せるもの」に変わります。

03 ／ 回転

同じ問題を、
90 度回すと EAA になる。

ここまでは、一つの開発主体の中の話でした。主体が複数になると、同じ崩れ方が別の軸で現れます。

「自律してよい」と宣言しても、
親が後から条件を直接書き換えられるなら、
判断権限は安定しない。

縦（層のあいだ）で「提起と承認を分ける」と言ったことと、横（主体のあいだ）で「提案と受入を分ける」と言うことは、同じ形です。基盤側から業務側への CI/CD 導入も、業務側から全体への用語訂正も、同じ関係になります。

AA ／ 中

上位の規範
↕
執行する層
↕
下位の規範

層のあいだ提起と承認を分ける

EAA ／ あいだ

主体
↔
主体
↕
主体

主体のあいだ提案と受入を分ける

そして、自治を宣言ではなく実体にしているのは、次の一行です。

上位の版が上がっても、
下位は自動では追随しない。

これがなければ、おおもとを改訂するだけで相手の義務が変わってしまいます。おおもとを改訂する権限と、それを採用する判断は、別のものです。

だから AA と EAA は、設計対象の名前です。AA は一つの主体の中、EAA は主体のあいだ。一つの主体が全責務を担う構成は 1 Cell の EAA であり、分割後の各主体を担うのも同じ AA です。段階の前後ではなく、見ている場所が違います。

EAA は内部方式を指定しません。相手が Agent を使うかどうかは接続の条件になりません。人間のチームも、外部の委託先も、同じ境界で接続できます。

04 ／ 根

釘を、どこに打つか。

自分を改訂する体系は、自分の正当性を自分では立てられません。どこかで再帰は止まります。この体系は、止まる場所を明記しています。

根の版は、所有者の承認そのものによって成立する。
その手続きは、体系の外にある。

根は人間です。内側の規範については改訂の循環を体系に入れ、根については外に置くと、書いてある。

これは穴ではなく、釘を打つ位置の宣言です。そしてここが、ほかの枠組みとの本当の差でした。監督の強度を可逆性で決める枠組みも、仕様を正本に据えた枠組みも、その決め方自体を誰がどう改訂するかを書いていない。書き忘れているというより、問いとして立っていない。

明示的に外に置くことと、問いとして立っていないことは、違います。

05 ／ 検証

最初に疑うのは、
委任の尺度だけにする。

八つ全部を同時に反証にかけると、どれが効いたのか分かりません。最初の一周で見直しの対象にするのは、(6)範囲は可逆性で、速度は期待浪費で決める——この一つだけです。その一つを、三つの数字で見ます。

  • 不可逆操作の、誤実行件数
  • 承認待ちで停止した、時間
  • 誤り一件あたり、発見までに進んだ実行量

二つ目が効きます。(6) は人間の判断を増やす方向にも働くので、増えた分を自分で数えるために置いてあります。「不要な判断をなくす」と「取り消せない操作は人間に通す」は、同じ資源を取り合う。どちらを優先するかは、取り合いが実際に起きてから、記録を根拠に決めます。先に決めれば、決めた理由が記録より古くなります。

仕組みを整える負担に対して判断を再利用できないなら、対象や任せ方のほうを見直します。

付記

例と数値は、説明のための仮定です。

ここでいう Agent は、計画し、道具を使い、実行結果を確かめて修正する AI を指します。

情報を参照できることと、権限を持つことは別に扱います。参照範囲を広げても、決定権は書かれたとおりです。

(8) が扱うのは、承認モードや許可リストのような、文書の形をとらない制約の緩和です。規範文書の改訂を扱う (4) とは対象が違い、片方だけでは穴が残ります。
