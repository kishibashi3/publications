| 第 0 章 | 巨大なシステムを Cell 一つで作れない理由を言える |
| 第 1 章 | Agent を職能で分ける案を、理由を付けて退けられる |
| 第 2 章 | 自分の現場で、Cell の境界をどこに引くか判定できる |
| 第 3 章 | Cell が引き受ける責務を、Profile に書ける |
| 第 4 章 | 相手の Cell の中を指定せずに、Cell どうしをつなげる |
| 第 5 章 | 残る結合を Contract に書き、仕事を Mission で頼める |
| 第 6 章 | 作った側を介さずに確かめられる Evidence を決められる |
| 第 7 章 | 相手の仕事を止めずに、取り決めの版を変えられる |
| 第 8 章 | 共有する文書の改訂を、誰が承認するか言える |
| 第 9 章 | Cell を分け直すとき、引き継ぐものを挙げられる |
| 第 10 章 | いまの分業から、最初に Contract に書くあいだを選べる |

**この本の読み手**　複数のチーム・複数の会社で開発するときに、チームのあいだの取り決め（インターフェース・受入の条件・版）を書いて持ち、採用するかを決めるエンジニア。

読み方は頭から通すか、第 0 章の次に要る章へ。

※ 上は CTO・開発部門の責任者まで。Cell の中は Agent でも人のチームでもよい（第 2 章）。語の意味と全体の絵は、第 0 章の終わりの全体図へ。
