# Enterprise Agentic Agile Core — 改訂草案

2026-09-22 · Kazuhiro

> Status: draft / proposed normative core
>
> Cell・Profile・Federationの整理を反映した現行のCore草案。
> 旧v0.1のファイルパスは参照互換のため維持する。承認済みの新版を意味しない。
> 読み方と変更の背景は [構成原理](eaa-cell-profile-federation-draft.md)、責務仕様は [Profiles](eaa-profiles-v0.1.md) を参照する。

## 1. 目的と範囲

EAAは、一つの自律系を必要に応じてCellへ分割し、各Cellの自律性を保ったまま全体の成果を成立させる構成原理である。
定めるのは、責務の分割方針とCell間の相互作用である。内部の開発方式は各Cellに委ねる。

[AA](../agentic-agile/README.md)は単独で成立する開発原則である。EAAは、その開発主体を一つのCellとして扱う。
AAが全責務を担う構成は1 CellのEAAであり、分割後に一つのCellを担うAAも同じAAである。
この対応づけと分割・接続の規則はEAA側で定め、AAの定義にEAAの概念を要求しない。
非AgenticなCellが一つあるだけでAAになるわけではない。
複数Cellでは、AA、Scrum、Kanban、Predictive、Vendor独自方式などが共存できる。

> 意味の違いまで共有し、内部実装は自治する。

## 2. 基本語彙

| 概念 | 定義 |
| --- | --- |
| Cell | 一定の目的に対する責任・権限・実行能力を持ち、外部との合意に基づいて自律的に成果を実現する単位 |
| Profile | Cellが引き受ける責務を定義する、版付きの仕様 |
| Mission | 責務のもとで今回実現する変化・成果 |
| Operator | Cellの成立条件、責任境界、権限、規範、例外判断を所有する人間 |
| Enabler | 顧客・関係者との文脈共有を通じて目的・優先順位・受入条件を具体化し、成果成立まで変化を進める人間 |
| Executor | 規範と権限の範囲で実行し、Evidenceを返す主体 |
| Ontology | Cellごとの意味の差を保持し、文脈から解釈可能にする意味体系 |
| Constitution | 採用した目的・価値・制約・権限・禁止事項を定める規範 |
| Contract | 相互の責任・提供条件・入出力・Evidenceなどを定める境界合意 |
| Evidence | 成果や判断の成立を検証可能にする記録 |
| Escalation | 自律実行の範囲を超えた判断を、正当な権限者へ戻すこと |

Enterprise／Domainは全体と部分という位置の呼び名である。
Platformなどの名前は担当責務を表す。Cellの基本構造を分けない。
Domainは責任領域を指し、その責務はDomain Profileで定義する。Domain Profileの数と独立Cellの数は一致しなくてよい。

EnablerとOpeに固定的な上下関係を置かない。顧客などが最終決定権を持つ場合、Enablerはその判断を成立させ、記録へ戻す。
CellごとにEnablerを常設する必要はない。
これらは責任を説明する役割であり、Federationが内部の職名・人数・工程を指定するものではない。
既存チームも、その外部責任と正当な判断主体を対応づけて参加できる。

## 3. C1 — 責務を先に定義する

必要なStandard／Domain Profileを列挙し、責任境界を定めてから、担うCellとOpeを決める。
一つのCellが複数Profileを引き受けてよい。
既存のAAを拡張するときは、その責務をEAA側でProfileとして記述する。Profileの用意をAAの開始条件にはしない。

Profileは、責務・目的・必要な権限と制約・外部とのContract・成立を示すEvidenceを定義する。
ロードは責務の引受であり、必要な権限と能力の確保を伴う。Profileの記述だけで権限が発生するわけではない。

内部方式や配置の具体例はReference Patternとする。
普遍的でない業務・専門領域の責務をCoreへ列挙しない。

## 4. C2 — 分割は自律した判断責任を渡すこと

判断負荷や専門性に応じ、責務と判断権限を別Opeへ引き渡して子Cellを形成できる。子Cellも同じ方針で分割できる。
すべての責務を元のCellで扱ってもよい。
再帰的に維持するのは、責任・権限・外部との合意・自治の境界であり、内部実装の同一性ではない。
子Cell群を持つCellも、外部には自らが引き受けた責任を果たす一つの主体として振る舞う。

作業だけを渡し、判断をすべて親へ戻す状態を独立Cell化とみなさない。
分離・再統合では、権限・資源・管理対象・記録・進行中Mission・残件を引き継ぐ。
同じ適用範囲の責任を空白にせず、決定権の重複を解消する。Profile解除によって未履行の保証は消えない。

## 5. C3 — Cellの自治

各Cellは、合意して採用した規範・Contractの範囲内で自律する。
他Cellは親Cellを含め、その判断を一方的に上書きしない。

実行方式、Agent基盤、モデル、内部工程、言語、DB、人間とAgentの分担は、合意した境界条件を満たす範囲で各Cellが決める。
全体責務や横断責務を持つことは、他Cellを強制変更する権限を意味しない。

新しい提案の不受入と、合意済み義務の一方的破棄は異なる。
履行不能や外部制約の変化は明示して調整する。自治を理由に既存の義務を消さない。

## 6. C4 — 意味と規範を版付きで共有する

Cell間の意思伝達は、共有OntologyとDomain・立場・文脈から解釈可能でなければならない。
営業の顧客、利用者、請求主体を一つに同化せず、違いと対応関係を保持する。

曖昧な意味を推測して越境せず、照会または変更提案で解消する。
Profileの適用・Mission・提案は、依存するOntology・Constitution・Contractの版を特定できるようにする。

上位規範の新版は下位へ自動適用しない。
規範自体の変更承認と、各Cellによる新版の採用判断を区別する。
採用中の規範を弱める権限を、実行者が自ら取得してはならない。

## 7. C5 — Missionと権限の境界

Missionは最低限、Goal、Constraints、Authority、Acceptance Evidenceを持つ。
背景と意味を共有し、引受条件を合意する。内部のTask分解は受入Cellへ委ねる。

子Missionは親Goalへの寄与を説明可能にする。
別の価値を発見した場合は、新MissionまたはGoal改訂を提案する。発見を理由に既存Missionの目的を無断変更しない。

Missionへの権限委任では、委任元が正当に与えられる範囲を越えない。

```
Authority(child mission) ⊆ Authority(parent mission)
```

これは委任範囲の条件であり、親Cellが分離後の子Cellを随時上書きできる根拠ではない。
予算・期限・契約などの外部条件を明示し、実行が成立しない場合は調整へ戻す。

## 8. C6 — 提案と受入

Cell間の変更は、提案側が内容・理由・根拠を示し、受入側が検証して受入・修正要求・不受入を判断する。
親子、兄弟、Platformなどの横断Cellに同じ原則を適用する。
GitHub PRはこの手順の実装例であり、必須製品ではない。

| 対象 | 判断 |
| --- | --- |
| 通常の実装・設定変更 | 対象Cellの既存規範と権限に従って受入判定する |
| 規範文書そのものの改訂 | その規範の正当な所有者が承認する |
| 上位規範の新版への移行 | 下位の所有者が採用を判断し、記録する |

AAと[自己改訂規範アーキテクチャ v1・最小構成](../self-revising-norm-architecture/self-revising-norm-architecture-minimal.md)に従う規範の所有者は人間であり、改訂の提起者はその改訂を承認しない。
通常のPR受入は、既存の権限の範囲でAgentが実施できる。自分を縛る規範を緩める変更の自己承認は認めない。

他Cellへの実装変更を提案できることと、その内部へ無断アクセス・変更できることは別である。
提案に必要な情報も、合意した参照・開示範囲で扱う。

## 9. C7 — Evidenceと来歴

Missionの完了は、作業実施・自己申告・PR mergeだけで成立しない。

```
Done
= Outcome achieved
+ Acceptance Evidence satisfied
+ Required contracts updated
+ Required decisions recorded
+ No unresolved authority violation
```

意思、Mission、派生Mission、実行、Evidence、受入・改訂の決定を追跡可能に残す。
一時的な会話だけに重要な決定を閉じ込めない。

Agentic CellではAAの生成と判定の分離に従う。
同じCellに属することは独立性を保証しない。規制などで必要な職務分離も維持する。

## 10. C8 — 人間判断を例外へ集中する

意味の不一致、境界の衝突、権限拡大、不可逆操作、検証不一致など、既存規範で判断できない問題を正当な判断主体へ戻す。
人間を通常の全件承認経路に置かない。

繰り返す判断は、根拠を残し、正当な改訂手続きを通じて規範・Contractへ反映する。
Enablerは反復する阻害を改善のMissionにする。
人間判断の削減と、成果・安全性の維持を一緒に観測する。

## 11. 未決の手順

構成原理として確定しているのは、責務を先に定義すること、分離後の自治、相互提案と受入、Evidenceによる成立確認である。
次の詳細は実装・実証を通じて定める。

- 合意不成立、履行不能、緊急時の調整・停止・返還・再編。
- 分離・再統合の移行条件と移行中の責任。
- 複数Cellにまたがる版互換性、受入・適用順序、部分失敗からの復旧。

未決事項を親Cellや横断Cellによる一方的な強制で補わない。
