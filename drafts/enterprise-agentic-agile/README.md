# Enterprise Agentic Agile（EAA）

単独で成立する[AA](../agentic-agile/README.md)から、責務の分割とFederationによって拡張する仕組み。
Cellの自律性を保ち、内部方式の異なる開発主体とも協働する。

## 読む順序

| 用途 | 文書 |
| --- | --- |
| 共通の境界を知る | [Core](enterprise-agentic-agile-core-v0.1.md)：責務と分割、自治、意味と合意、変更、成果と記録 |
| 引き受ける責務を定める | [Profiles](eaa-profiles-v0.1.md)：仕様、引受・改訂・解除、Standard／Domain |
| 設計の理由を理解する | [解説](eaa-cell-profile-federation-draft.md)：AAからの拡張と分割例 |
| 実際に運営する | [Delivery Guide](eaa-delivery-guide-v0.2.md)：GitHub・記録・運営の選択例 |
| 役割を配置する | [Role Model](eaa-role-model-v0.1.md)：適用ガイドの役割編 |
| 既存組織へ導入する | [Adoption Guide](eaa-adoption-guide-v0.1.md)：導入・役割移行の例 |

CoreとProfilesが仕様の定義元であり、解説・適用ガイドは新たな義務を追加しない。
これらは草案である。詳細スキーマやFederationの状態遷移は未確定で、ファイル名の版表記は承認・採用を意味しない。
規範の改訂の共通基盤は[自己改訂規範アーキテクチャ](../self-revising-norm-architecture/README.md)を参照する。
