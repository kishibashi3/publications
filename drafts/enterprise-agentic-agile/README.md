# Enterprise Agentic Agile（EAA）

単独で成立する[AA](../agentic-agile/README.md)から、責務の分割とFederationによって拡張する仕組み。
Cellの自律性を保ち、内部方式の異なる開発主体とも協働する。

## 読む順序

初めて読む場合は、考え方と開発の姿、原則・仕様、必要な適用例の順に読む。
運用中に仕様を確認する場合はCoreとProfilesを直接参照する。

| 段階 | 文書 | 位置づけ |
| --- | --- | --- |
| 1. 考え方と開発の姿 | [導入解説](eaa-cell-profile-federation-draft.md) | AAからの拡張、分割とFederationの理由、具体例。非規範 |
| 2. 原則・仕様 | [Core](enterprise-agentic-agile-core-v0.1.md) | 責務と分割、自治、意味と合意、変更、成果と記録 |
| 2. 原則・仕様 | [Profiles](eaa-profiles-v0.1.md) | 責務仕様、引受・改訂・解除、Standard／Domain |
| 3. 詳細解説・適用例 | [Delivery Guide](eaa-delivery-guide-v0.2.md) | GitHub・記録・運営の選択例。非規範 |
| 3. 詳細解説・適用例 | [Role Model](eaa-role-model-v0.1.md) | 適用ガイドの役割編。非規範 |
| 3. 詳細解説・適用例 | [Adoption Guide](eaa-adoption-guide-v0.1.md) | 導入・役割移行の例。非規範 |

CoreとProfilesが仕様の定義元であり、解説・適用ガイドは新たな義務を追加しない。
これらは草案である。詳細スキーマやFederationの状態遷移は未確定で、ファイル名の版表記は承認・採用を意味しない。

## 検討履歴・参考資料

[Working Notes](enterprise-agentic-agile-working-notes.md)は理論との接続・10億円ケース・観測方法、
[比較資料](eaa-enterprise-agile-comparison-v0.1.md)は旧モデルの評価・設計変更の履歴・再評価計画を残す。
現行仕様の判断にはCoreとProfilesを用いる。
