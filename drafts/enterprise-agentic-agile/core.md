# Enterprise Agentic Agile Core

> 位置づけ：規範案（未確定）
> 対象：Cellの責務分割・自治・意味と合意・変更・成果と記録の定義。
> 参照：責務仕様は[Profiles](profiles.md)。解説・適用例は本書に規範を追加しない。

## 0. 目的と範囲

EAAは、自律した開発主体をCellとして扱い、責務の分割とFederationによって拡張する構成原理である。
[AA](../agentic-agile/README.md)が全責務を担う構成は1 CellのEAAであり、分割後のCellを担うAAも同じAAである。
AAは単独で成立する。Federationは内部方式を指定せず、AA以外の開発主体も接続できる。

| 概念 | 定義 |
| --- | --- |
| Cell | 一定の目的に対する責任・権限・実行能力を持ち、外部との合意に基づいて自律的に成果を実現する単位 |
| Profile | Cellが引き受ける責務を定義する、版付きの仕様 |
| Mission | 責務のもとで今回実現する変化・成果 |
| Ontology | 意味の違いと対応を保持し、文脈から解釈可能にする意味体系 |
| Constitution | 採用した目的・価値・制約・権限・禁止事項を定める規範 |
| Contract | 相互の責任、提供条件、入出力、必要なEvidenceを定める境界合意 |
| Evidence | 成果や判断の成立を検証可能にする記録 |

## 1. 責務と分割

必要な責務をProfileとして定義し、担うCellと正当な判断責任者を明らかにする。
一つのCellが複数Profileを担ってよい。Profileの記述だけで権限は発生せず、引受には必要な権限・資源・能力の確保を伴う。

分割は、責務と自律的な判断権限を別の責任主体へ引き渡すことである。
子Cellも同じ方針で分割できる。再帰的に維持するのは責任・権限・合意・自治の境界であり、内部実装の同一性ではない。
子Cell群を持つCellも、外部には自らが引き受けた責任を果たす。

分離・再統合・責務解除では、権限・資源・管理対象・記録・進行中Mission・残件を引き継ぐ。
責任の空白や決定権の重複を残さず、未履行の保証を消さない。外部保証を変える場合は関係者と再合意する。

## 2. 自治と権限

各Cellは、合意して採用した規範・Contractの範囲で内部方式と実行を決める。
他Cellは親Cellや横断責務を担うCellを含め、その判断を一方的に上書きしない。

MissionはGoal、Constraints、Authority、Acceptance Evidenceを明示し、背景と引受条件を共有する。
内部のTask分解は受入Cellへ委ねる。権限を委任する場合、委任元が正当に与えられる範囲を越えない。
子Missionは親Goalへの寄与を説明可能にし、目的を変える場合は新Missionまたは改訂として提案する。

提案できることは、他Cellへの無断アクセス・変更権限を意味しない。情報も合意した参照・開示範囲で扱う。
新しい提案を受け入れないことと、既存義務の一方的破棄は異なる。履行不能や既存権限で判断できない問題は明示し、正当な判断主体との調整へ戻す。

## 3. 意味と合意

Cell間の意思伝達は、Ontologyと立場・文脈から解釈可能にする。
意味の違いと対応を保持し、曖昧さを推測で越境せず、照会または変更提案で解消する。

Profileの引受、Mission、提案では、依存するOntology・Constitution・Contractの版を特定する。
規範の新版公開と各Cellの採用は別の行為であり、自動追随しない。採用中の合意は移行が成立するまで有効である。

## 4. 提案と変更

Cell間の変更は、提案側が内容・理由・根拠を示し、対象Cellが検証して受入・修正要求・不受入を判断する。
親子・兄弟・横断に同じ原則を適用する。

| 対象 | 判断主体 |
| --- | --- |
| 実装・設定の変更 | 対象Cellの既存規範と権限で定めた受入主体 |
| 規範の改訂 | その規範の正当な所有者 |
| 規範の新版の採用 | 採用側の規範の正当な所有者 |

各判断は適用される承認手続きに従う。規範の新版の採用は、通常の実装・設定変更の受入権限だけでは判断できない。
AAおよび[自己改訂規範アーキテクチャ v1・最小構成](../self-revising-norm-architecture/self-revising-norm-architecture-minimal.md)に従う規範体系では、所有者は人間であり、改訂の提起者はその改訂を承認しない。
この参照は、参加Cellの内部規範に同アーキテクチャの採用を要求するものではない。内部の改訂手続きは各Cellが定め、Cell間の合意の変更と採用には本書の境界条件を適用する。
実行者が自分を縛る規範を緩める変更を自己承認したり、自ら権限を拡大したりしてはならない。
Profile正本の改訂と採用版の扱いは[Profiles](profiles.md)で定める。

## 5. 成果と記録

Missionの完了には、Outcomeの達成、Acceptance Evidenceの充足、必要なContract更新と判断記録、権限違反の解消を要する。
作業実施や変更の受入だけでは完了しない。合意した検証条件と必要な職務分離を維持する。

意思、Missionとその派生、実行、Evidence、受入、改訂、引継ぎを追跡可能に残す。
重要な決定を一時的な会話だけに閉じ込めない。

## 未決の手順

合意不成立・外部制約変化・緊急時の調整、移行中の責任、複数Cell変更の互換性・適用順・部分失敗からの復旧は、詳細手順を今後定める。
未決事項を他Cellからの一方的な強制で補わない。
