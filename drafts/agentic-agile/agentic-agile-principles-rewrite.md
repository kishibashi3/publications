# Agentic Agile Principles v2（書き直し案）

2026-09-19 · Kazuhiro

本書は、AIエージェントが開発の実行主体となる環境における開発の原則を定める。準拠先は「[自己改訂規範アーキテクチャ v1・最小構成](../self-revising-norm-architecture/self-revising-norm-architecture-minimal.md)」である。

本書の「agile」は、特定の宣言や枠組みではなく、素早さそのものを指す。前提が変わって答えが変わる部分だけを書き、変わらない部分は書かない。

## 1. 規範文書としての項目

| 項目 | 内容 |
| --- | --- |
| 目的 | 人間の判断を、最も価値のある判断に使い切る |
| ルール | 第3章の原則と、第4章の指針 |
| 実行者 | 本書に準拠して案件規則を作り、運用する人間とエージェント |
| 所有者 | Kazuhiro |
| 観測 | 本書に準拠する案件規則の改訂記録のうち、本書が妨げになった、または不足していた事例 |
| 見直しの契機 | 上記の事例が記録されたとき |
| 準拠先 | [自己改訂規範アーキテクチャ v1・最小構成](../self-revising-norm-architecture/self-revising-norm-architecture-minimal.md) |

## 2. 前提

実行は安く、速いが、総量には上限がある。希少なのは人間の判断と、実行の総量である。出力は確率的にばらつき、同じ生成元は同じ誤りを共有する。

## 3. 原則

| ID | 原則 | 言明 |
| --- | --- | --- |
| P1 | 権威は書かれたものに宿る | 実行者が従うのは、書かれたルールと書かれた価値だけである。書かれていないものは、存在しないものとして扱う |
| P2 | 開発は憲法の連鎖である | 各層は、自らの憲法に従って執行し、下位の憲法を書く。実行者が人間かエージェントかを問わない |
| P3 | 憲法は改訂される | 憲法は観測を根拠に改訂される。改訂の手続きは準拠先に従う |

## 4. 原則から導かれる指針

出典には原則と前提を挙げる。他の指針を前提に取る指針は、その指針も出典に挙げる。

| ID | 指針 | 導出 |
| --- | --- | --- |
| D1 | 判断の配分 | 希少な判断を、最も価値のある判断に配分する。不要な判断をなくすことも成果である（P1・前提） |
| D2 | 意味の一意性 | 語の意味は文脈ごとに一つとし、変更は版として行う（P1） |
| D3 | 生成と判定の分離 | 判定は、生成と異なる主体またはモデルの系列で行う。自らの成果を自ら承認しない（P1・P2・前提） |
| D4 | 委任の尺度 | 自律の範囲は可逆性が、自律の速度は期待浪費（誤り確率 × 実行量）が決める。範囲の外に置くものは D8 が別に定める。責任は人間に留める（P2・前提） |
| D5 | 確率的品質 | 品質は点ではなく分布として扱う（前提） |
| D6 | 境界 | 実行者が参照・送信できる情報は、役割に応じて最小化する（P2） |
| D7 | 可逆性は設計で買える | 小さく刻むとは、可逆性を買う行為である。ただし刻んだ全体が一箇所から見えること。累積が不可逆なら、判断は累積に対して求める。D8 が範囲の外に置くものは、刻んでも買えない（D4・D8・前提） |
| D8 | 自己権限の固定 | 実行者は、自らを縛る規則を緩める変更を自ら承認しない。取り消せることは、この種の変更を自律に渡してよい理由にならない（P1・P2・前提） |

## 5. 最初の循環で検証する項目

最初の循環では D4 だけを検証する。検証は、本書に準拠する案件規則の運用を通じて行う。

| 項目 | 見直し条件 | 観測 |
| --- | --- | --- |
| D4 | 可逆性と期待浪費に基づく委任が、不可逆操作の誤実行を招いた、または承認待ちで過剰に停止した | 不可逆操作の誤実行件数、承認待ちで停止した時間、誤り一件あたりの実行量 |

## 6. 後回しにしたもの

他の指針の反証・見直し条件、価値の優先順位、本書を執行するエージェントの構成は、必要になった時点で、記録を根拠に追加する。
