# Agentic Agile Principles v1

2026-09-19 · Kazuhiro

本書は、AIエージェントが開発の実行主体となる環境における開発の原則を定める。準拠先は「自己改訂規範アーキテクチャ v1」である。原則の成立理由は「解説」タブに置く。

本書の「agile」は、特定の宣言や枠組みではなく、素早さそのものを指す。前提が変わって答えが変わる部分だけを原則として書き、変わらない部分は書かない。

## 1. 規範文書としての項目

| 項目 | 内容 |
| --- | --- |
| 目的 | G1：価値を早く継続的に届ける |
| ルール | 第2章の原則 |
| 実行者 | 本書に準拠して案件規則を作り、運用する人間とエージェント |
| 所有者 | Kazuhiro |
| 観測 | 本書に準拠する案件規則の改訂記録のうち、本書の原則が妨げになった、または不足していた事例 |
| 見直しの契機 | 上記の事例が記録されたとき |
| 準拠先 | 自己改訂規範アーキテクチャ v1 |

## 2. 原則

| ID | 原則 | 言明 |
| --- | --- | --- |
| A1 | 判断の配分 | 実行は安価であり、人間の判断が希少資源となる。希少な判断を、最も価値のある判断に配分する。不要な判断をなくすことも成果である |
| A2 | 明示性 | 明示されていない意味は、存在しないものとして扱う。語の意味は文脈ごとに一つとし、変更は版として行う |
| A3 | 確率的品質 | 品質は点ではなく分布として扱う |
| A4 | 相関誤りの排除 | 同じモデルが同じ文書から生成したものは、同じ誤りを共有しうる。判定は、生成と異なる主体またはモデルの系列で行う |
| A5 | 段階的委任 | 自律は計測された信頼に応じて与え、責任は人間に留める |
| B1 | 境界 | エージェントが参照・送信できる情報は、役割に応じて最小化する |

## 3. 最初の循環で検証する項目

最初の循環ではA5だけを検証する。検証は、本書に準拠する案件規則の運用を通じて行う。

| 項目 | 見直し条件 | 観測 |
| --- | --- | --- |
| A5 | 一致率に基づく委任が、誤った自動化または過剰な人間の判断を招いた | 判定の種類ごとの人間とエージェントの一致率、委任後の見逃し |

## 4. 後回しにしたもの

他の原則の反証・見直し条件、価値の優先順位、本書を執行するエージェントの構成は、必要になった時点で、記録を根拠に追加する。
