# 承認台帳

> 位置づけ：記録（非規範）
> 対象：本リポジトリの規範文書に対する、所有者の採否。
> 参照：記録の義務は[自己改訂規範アーキテクチャ v1・最小構成](../self-revising-norm-architecture/self-revising-norm-architecture-minimal.md) §2、採用内容の固定は[文書管理](../document-management.md)に従う。

## この台帳について

本書は、最小構成 §2 の「評価・改訂の提起・採否を、追記のみの記録に残す」の置き場所である。
1 行に 1 件、所有者がどの文書のどの版を、どの内容で承認したか、または承認しなかったかを残す。評価と提起の本文は PR・issue・レビュー記録に残り、行の「根拠」欄から参照する。

文書が正本であることは、本書に承認の行があることで示す。冒頭の「位置づけ」欄の記述や、commit・merge の存在だけでは示さない（文書管理「履歴・承認・採用」）。

## 本書の位置づけ

本書は記録であり、規範ではない。所有者・観測・準拠先を持たず、本書自身を承認する行も置かない。
本書を規範にすると、本書にも承認の行が要り、最初の行が本書自身を承認する行になる。

表より上の案内は、最小構成 §2 と文書管理から書き方を導いたもので、義務を追加しない。案内と最小構成が食い違うときは、最小構成に従う。
行を承認として数えるかどうかは、本書では判定しない。判定は最小構成 §2 に従う。本書は、判定に要る事実を残す。

## 書き方の規則

- 追記のみとする。既存の行を書き換えない・消さない・並べ替えない。
- 行は承認者本人が書く。起案者・レビュー者・エージェントが代わりに書かない。提起者が承認の行を書くと、提起者が承認したのと区別できない。
- 訂正は、前の行を残して新しい行を足す。種別を「訂正」とし、備考に訂正する行（判断日と文書）と、何をどう改めるかを書く。
- 取り消しも同じく新しい行で書き、種別を「取消」とする。
- 表より上の案内を変えても、既存の行は書き換えない。

## 列

| 列 | 書くこと |
| --- | --- |
| 判断日 | 承認者が判断した日（`YYYY-MM-DD`）。特定できない場合は、根拠から言える範囲（例：`2026-09-23 以前`）で書き、推定で一日に絞らない |
| 記入日 | この行を書いた日（`YYYY-MM-DD`） |
| 種別 | 承認／不承認／訂正／取消／適用。適用は、承認済みの差分が文書に当たった commit を残す行で、新しい判断ではない。備考に対応する承認の行を書く |
| 文書 | リポジトリとパス。パスは commit 欄の commit 時点のものを書き、後でファイルが移っても書き換えない。1 行に 1 文書とし、複数の文書にかかる承認は文書ごとに行を分ける |
| 版 | 文書の規範上の版識別子。起案の改訂番号（rev.N）ではない。文書に版が無い場合は「未設定」と書き、SHA で代用しない（文書管理「採用内容の固定」） |
| commit | 承認した内容を特定する完全なコミット SHA。まだ文書に当たっていない差分を承認した場合は、差分の置き場所（リポジトリ・パス・SHA）を書き、当たった後に「適用」の行を足す |
| 提起者 | 改訂を提起した者。起案した者と内容を決めた者が違う場合は、両方を役割とともに書く |
| 承認者 | 判断した人間 |
| 根拠 | 提起と評価が残っている場所（PR・issue・レビュー記録） |
| 備考 | 下記の印、訂正・取消・適用の対象となる行 |

## 印

備考欄に、該当するものを書く。

- **遡及**：判断日と記入日が違う行。既にあった判断を後から記録するもので、判断をやり直すものではない。備考に、判断があったことを示す既存の記述の場所（ファイル・行・commit）を書く。記入の時点で判断をやり直す場合は、遡及ではなく、その日の承認の行として書く。
- **提起者＝承認者**：提起者と承認者が同じ人になる行。隠さずにそのまま書き、なぜそうなったか（最小構成 §4 の根である、最小構成の内側に入る前の立ち上げである、等）を書く。その行を承認として数えるかは、最小構成 §2 に従って判定される。

## 本書に書かないもの

- **他のCellでの採用の承認**。EAA の規範を採用する承認は、採用するCellの規範の所有者が行い、そのCellが記録を管理する。本書は、本リポジトリの規範文書の所有者の判断だけを残す。
- **採用記録のうち、本リポジトリの規範文書の所有者に示す部分**（EAA Core の観測欄の入力）。何を示すか、どこに置くかは Core の観測欄の側で定める。本書に写すと、Cellが管理する記録の写しが所有者の側にでき、どちらが正か分からなくなる。観測から改訂が提起され、所有者が採否を判断したときに、その判断を本書に残し、観測の記録を根拠欄から参照する。

## 最初の行の書き方（案内）

次の 2 件は、承認者が書く予定の行である。欄の埋め方だけを示し、値の確定は承認者が行う。

### AA Principles を正本とした承認

- **遡及**の行になる。判断は既にあり、`drafts/document-management.md` の「今回の所有者の承認に基づく」の 1 文だけが残っている。この文には日付も版も無い。
- 判断日：この文が入った commit `29d565161b46ce5f1900118f420653c103f576a2` の日付（2026-09-23）は、判断がその日までにあったことしか示さない。承認者が日を覚えていればその日、覚えていなければ `2026-09-23 以前` と書く。
- 文書：`drafts/agentic-agile/principles.md`（上の commit 時点のパス）。
- 版：principles.md には版の欄が無いので「未設定」。版を付けるには文書の改訂が要り、それは別の承認になる。
- commit：承認した内容の SHA。principles.md をこのブランチで最後に変えた commit は上の `29d5651…` だが、承認したのがこの内容かは承認者が確かめて書く。
- 提起者：書き直し案を起案した者。git の author からは特定できないので、承認者が確認して書く。
- 備考：「遡及」と、根拠の記述の場所（`drafts/document-management.md`、commit `29d5651…`）。

### EAA Core 修正案 rev.2 の承認

- 差分は `core.md` と `profiles.md` の 2 文書にかかるので、**文書ごとに 2 行**になる。
- 版：core.md は差分で冒頭に足す `1`。rev.2 は修正案の改訂番号で、文書の版ではない。profiles.md は版の欄を持たないので「未設定」。
- commit：差分はまだ文書に当たっていないので、差分の置き場所を書く。当たった後、publications の commit を「適用」の行として足す。差分の置き場所が非公開のリポジトリにある場合、本リポジトリの読み手はその内容を確かめられない。
- 提起者：起案と内容の決定が別の者にある（起案 @deep-research、内容の決定は所有者）。両方を役割とともに書く。所有者が内容を決めているので、**提起者＝承認者**の印に当たるかを承認者が判断し、当たる場合は備考に理由を書く。
- 根拠：修正案と、レビュー記録（Approve）の場所。
