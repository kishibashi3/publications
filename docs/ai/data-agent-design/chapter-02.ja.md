# 第2章：選択基準の透明性 ― 判断はデータと同格に観測可能でなければならない

## ―残された課題を、公理まで遡って解く

---

## 2.1 第1章が残した課題の再確認

第1章は、Platinum という実行時ウィンドウの設計によって、データそのものが静かに失われる失敗（サイレント切り詰め）を解決した。1.3.3 の階段は「宣言のない縮小はどのステップにも属さない不正な状態である」という一文で、この種の失敗を検出可能にした。

しかし 1.3.7 で述べたとおり、この設計にはもう一つの失敗モードが残っている。**何を残し何を落とすかという選択基準そのものが誤っていて、しかもその誤りが静かに埋没する**というケースである。宣言メカニズムは「どれだけ落としたか」を検出できても、「なぜその基準で落としたか」が問いの意図とずれていたかどうかまでは検出できない。データは正しく縮小されているのに、判断は間違っている——この二つは独立した失敗軸であり、第1章は前者しか閉じていない。

本章はこの残された失敗モードを、単発の追加機能としてではなく、本シリーズが依拠する Core の公理系から演繹する形で閉じる。

## 2.2 選択基準は、観測されなければ存在しない

Core 第1章は、存在の条件を次のように定義する。

> 公理1：存在するとは、観測可能な秩序をもつことである。
> 公理2：無だけが非システムである。

この二つの公理を、選択基準というサブシステムに適用するとどうなるか。選択基準とは、エージェントが「有効顧客」をどう定義したか、どの粒度で集約したかという、応答の背後にある判断の秩序である。この秩序が応答に付随せず、後から検証も監査もできないなら、それは公理1の条件——観測可能な秩序を持つこと——を満たさない。

ここで注意すべきは、選択基準そのものが消えているのではないという点だ。エージェントは判断を下しており、その判断は確かに実行されている。しかし判断が観測可能な形で外部化されていなければ、公理1の基準に照らす限り、それは「存在しない」のと区別がつかない。1.3.7 で述べた「その誤りが静かに埋没する」という現象論的な言い方は、ここで公理レベルの記述に置き換えられる——**観測されない選択基準は、公理2のいう無の位置に落ちる**。

これは第1章 1.2 で述べた「無が存在を僭称している」構造の再来である。1.2 ではサイレント切り詰めによって消えた行・列が無でありながら「成功」という秩序を装って返ってきた。選択基準のサイレント化では、消えるのはデータではなく判断そのものだ。判断が無に沈んでいるにもかかわらず、応答は「正しく縮小されたデータ」という観測可能な秩序を装って返ってくる。**サイレント切り詰めがデータの僭称だったのに対し、選択基準のサイレント化は判断の僭称である。**

ここで一つの反論が原理的に成立しうる。応答データそのものは観測可能であり、そこから基準を逆算できるのではないか、という反論である。しかしこれは成立しない。**複数の異なる基準が同一の縮小結果を生成しうる**（アンダーデターミネーション）ため、データの観測は基準の一意な観測を含意しない——「解約日が期間内に存在しない顧客」と「先月中に一度でも取引があった顧客」は、対象期間によっては同一の集合を返しうるが、両者は問いの意図に対してまったく異なる含意を持つ。応答データの観測可能性は、選択基準の観測可能性の代替にはならない。この点の実務上の帰結は 2.5 の三点目（基準の正しさの保証は範囲外）に吸収される。

## 2.3 熱的透明性の敷衍 ― 温度から判断基準へ

この構造は、実は本シリーズの外側で先に定式化されている。Core 第5章 5.5「AIと再関係」は、AIの設計原理を次の二つに要約する。

> **関係保存則**　AIは、既存の人間関係を破壊する設計をしてはならない。
> **熱的透明性**　AIは、やり取りの温度（T）を可視化し、関係の冷却／加熱を管理する。これにより、過熱や凍結を事前に検知できる。

熱的透明性は、もともと「関係の温度」を対象にした原則である。しかし、この原則が要請しているのは温度そのものの可視化ではなく、**エージェントが下している判断を、事後的に検証可能な形で外部化すること**という、より一般的な要請だ。関係の冷却・加熱という現象は、AIが下している判断（どう応答するか、どこまで踏み込むか）の一つの表れにすぎない。判断が可視化されていれば、その判断がもたらす結果（過熱・凍結）も事前に検知できる、という順序で原則は組み立てられている。

選択基準の可視化は、この同じ原則を「関係の温度」という対象から「データの取捨選択という判断」という対象へ、対象を差し替えて適用したものにすぎない。原則そのものは変わらない——**判断が可視化されていなければ、その判断が引き起こす失敗を事前に検知できない**。第1章が閉じたのはデータの温度（縮小の度合い）の可視化であり、本章が閉じるのは判断の温度（基準そのもの）の可視化である。同じ熱的透明性という一つの原則が、対象を変えて二度、この一つのシリーズの中で具体化されていることになる。

## 2.4 V(S) の前提条件としての透明性

Core 第6章は、システム価値を次の式で定式化する。

$$V(S) = \sum_{i} V(s_i), \quad s_i \in \text{Sが生存期間Tにおいて創発したサブシステム}$$

この定義は再帰的であり、外部基準を持たない。$V(s_i)$ もまた同じ定式で定義される——つまり、あるサブシステムの価値は、それが内包するさらに小さなサブシステムの価値の総和として、どこまでも遡って定まる。

ここで、データエージェントというシステム $S$ を考える。選択基準というサブシステム $s_i$ の価値 $V(s_i)$ が観測されないまま、上位の判断——エージェントの応答全体の価値——に組み込まれるとどうなるか。$V(S)$ は $V(s_i)$ の総和として定義されているのに、その項の一つが観測不能であれば、総和という演算自体が実行できない。観測できない項を「ゼロとして無視する」のか「正しいと仮定して合算する」のか、どちらを選んでも、$V(S)$ の値は実態を反映しなくなる。**V の算定自体が虚偽になる。**

したがって、透明性は倫理的な美徳や、後から付け加えられる説明責任の要求ではない。**それは V(S) という価値計算が成立するための、数式レベルの前提条件である。** 選択基準を観測可能にすることは、「良心的なエージェントであるための努力目標」ではなく、「そもそもこのシステムの価値を計算できるようにするための必要条件」として位置づけられる。この位置づけの転換こそが、本章が第1章から一段深く進む点である。

## 2.5 設計原則 ― 選択基準を宣言と同格の一級市民にする

以上の演繹から、設計原則は次のように定まる。

第1章 1.3.3 の階段は、④（密度・精度を落とす）を使うときに「何を、どれだけ落としたか」を宣言することを要求した。この宣言は、データという観測対象についての秩序だった。本章が要求するのは、これと同じ扱いを**選択基準そのもの**にも与えることである。

- **データの宣言**（第1章）：「売上を月単位の SUM に畳んだ」
- **基準の宣言**（第2章）：「有効顧客＝解約日が期間内に存在しない顧客、として解釈した」

前者はデータがどう変形されたかを述べ、後者はなぜその変形が選ばれたかを述べる。両者は独立した宣言であり、片方があれば他方が要らないという関係にはない。1.3.3 の階段を正しく降り、④で宣言まで済ませていても、そもそもの解釈——「有効顧客」をどう定義したか——が問いの意図とずれていれば、階段の宣言メカニズムはこの種の誤りを一切検出しない。基準の宣言は、階段とは別のレイヤーで、階段に入る前の判断を対象にする。

この基準の宣言に、公理1の条件を厳密に適用すると、次の要件が導かれる。

1. **応答に付随すること** — 選択基準は、別途要求されたときにだけ開示される付加情報ではなく、応答そのものの一部として毎回出力される。観測可能性は、要求されて初めて成立するものではなく、常時成立していなければならない（公理1が「観測可能な秩序」を要求するのであって「要求すれば観測できる秩序」を要求するのではない）。
2. **事後に検証・監査できること** — 出力された基準は、後から人間または別のエージェントが「この基準は問いの意図に合っていたか」を確認できる形式で保存される。観測可能性は、その瞬間限りの表示では足りない。持続する記録として残らなければ、公理1の要求は満たされない。
3. **基準の正しさそのものは別問題として切り離すこと** — 本章が要求するのは可視化であって、基準の正しさを保証する仕組みではない。基準が正しいかどうかの検証・改善は、可視化された記録があって初めて可能になる後続の作業であり、この章の範囲を超える。

三点目は重要な線引きである。本章は「選択基準を正しくする方法」を示さない。示すのは「選択基準を、正しいかどうか判定可能な状態に置く方法」だけだ。この違いは、第1章が「サイレント切り詰めを防ぐ方法」を示したのであって「常に完璧な縮小を行う方法」を示したのではないのと同じ構造を持つ。どちらの章も、失敗を検出可能にすることを目的とし、失敗そのものをゼロにすることは目的としない。

## 2.6 具体例 ― 同じ問いに、二つの宣言を添える

「先月の有効顧客の売上は？」という問いを、第1章 1.3.3 の末尾で示したエージェントの手順に沿って追ってみる。

エージェントはまず①有効顧客テーブルと当該月の期間で行を絞り、②売上額・顧客ID・日付以外の列を落とし、③顧客単位ではなく月単位の SUM に畳む。ここまでで応答可能なサイズに収まったとすると、第1章の要求に従い、エージェントは「月単位の SUM に畳んだ」というデータの宣言を添えて答えを返す。

本章はこれに加えて、もう一つの宣言を要求する。「有効顧客」という語をエージェントがどう解釈したか——「解約日が期間内に存在しない顧客」として扱ったのか、それとも「先月中に一度でも取引があった顧客」として扱ったのか——という基準そのものを、データの宣言と並べて出力する。

この二つの宣言が揃って初めて、人間は二段階の確認ができるようになる。第一に、階段の縮小が正しく行われたか（第1章の関心）。第二に、そもそも入口の解釈が問いに合っていたか（本章の関心）。どちらか一方の宣言だけでは、この二段階の確認は成立しない。

## この章のまとめ

- **第1章が残した課題**: サイレント切り詰め（データの消失）は解決したが、選択基準そのものの誤りが静かに埋没する失敗モードは未解決だった
- **公理からの再定式化**: 観測されない選択基準は、公理1（観測可能な秩序をもつことが存在である）を満たさず、公理2（無だけが非システムである）のいう無の位置に落ちる。データの僭称（第1章）に対して、これは判断の僭称である
- **熱的透明性の敷衍**: Core 第5章5.5「AIは、やり取りの温度を可視化し、関係の冷却／加熱を管理する」という原則は、対象を「関係の温度」から「判断の基準」に差し替えても同じ形で成り立つ。判断が可視化されていなければ、その判断が引き起こす失敗を事前に検知できないという原則自体は不変である
- **V(S) の前提条件**: システム価値 $V(S) = \sum_i V(s_i)$ は再帰的で外部基準を持たない。選択基準というサブシステムの価値が観測されないまま上位の判断に組み込まれれば、総和という演算自体が実行できず、V の算定が虚偽になる。透明性は倫理的美徳ではなく、価値計算が成立するための数式レベルの前提条件である
- **設計原則**: 選択基準の宣言を、データの宣言（第1章 1.3.3 の階段④）と同格の一級市民として応答に含める。応答に常時付随し、事後に検証・監査でき、かつ基準の正しさそのものの保証は後続の課題として切り離す
- **第1章との関係**: データの宣言（何を、どれだけ落としたか）と基準の宣言（なぜその基準を選んだか）は独立した二つの宣言であり、どちらか一方では他方の失敗を検出できない
