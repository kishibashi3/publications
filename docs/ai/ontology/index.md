# オントロジー

> **モデルは解釈だ。オントロジーは、その一段手前にある記述だ。**

---

## 📚 目次

### [第1章：分裂と摩擦 ― なぜ語彙は揃わないのか](./ch1-fragmentation-and-friction.md)

現実をモデルに合わせるのではなく、現実の語彙を先に記述しておく。分裂を統一せず保持することが、AI時代のシステム開発とエージェント利用に欠けていたものだ。

### [第2章：仮説を先に持つ ― ヒアリングの前に立つオントロジー](./ch2-hypothesis-before-hearing.md)

業務資料から抽出した語彙は、ヒアリングの前に仮説として使える。ヒアリングは「白紙から聞く」作業から「仮説を確認する」作業に変わり、設計の仮定を問い返す視点と、組織の都合ではなく語彙の性質でシステム境界を引く根拠が手に入る。
